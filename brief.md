# Test automation project for Todoist

- security - use secrets manager - github action secrets, .env file (gitignored)
- use the test cases provided by testers for the test automation
- requirements and acceptance criteria - we don't have them
- tools - playwright with typescript
- environments - currently just production, but prepare it for others (test, dev...) 
- endpoints - https://developer.todoist.com/api/v1/
- coding style - use best practices
- pipelines - use github actions, run tests with every PR, smoke tests every hour
- commit messages - include issue id, brief summary of changes
- reporting - playwright html report stored in github actions pipeline artifacts, keep traces file in the pipeline artifacts
- project structure - use best practices, object oriented approach, keep test data separate
- for business, the key functionality is working with tasks
- test data should be generated by every test and cleaned up afterwards
- test cases should contain steps
- automation goal - quick feedback, help regression testing
- we are not going to automate sections because it is going to be changed in the next release
- test case name should contain the test id in the tag and the name
- use the best practices for test case design
- organize test cases into test suites, use tags (smoke, regression, e2e, negative)
- use eslint for static analysis
- use prettier
- use git hook to protect the main branch
- every change should create an issue > branch > PR
- do not merge PRs
- every PR should be reviewed 
- every time you finish creating a PR, give me the url to PR and a brief summary of changes
